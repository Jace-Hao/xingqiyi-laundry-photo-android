# 移动端 v1.0.0 发布说明

移动端自本版起**独立成库、独立编号**。

| 项目 | 仓库 | 版本来源 |
|---|---|---|
| 桌面端 | `Jace-Hao/xingqiyi-laundry-photo` | `package.json` → `version` |
| **移动端（本仓库）** | `Jace-Hao/xingqiyi-laundry-photo-android` | `app/build.gradle.kts` → `versionName` |

- **移动端版本号从 v1.0.0 重新计数**。此前移动端挂在桌面端仓库里、跟着桌面端编号
  （1.3.0 / 1.3.1），导致桌面端自动更新把移动端的 APK 当成「新版本」推给电脑用户。
- **桌面端版本线修正为 1.2.x**：本次同步把桌面端原本误编的 1.3.0 更正为 **v1.2.3**
  （上一正式版为 v1.2.2），此后依次 1.2.4、1.2.5……
- 两端各自发布到自己的仓库，互不干扰。

> ⚠️ 本版 `versionCode` 为 **10500**，与 `versionName` 不再有换算关系。
> `versionCode` 是给 Android 系统看的单调计数器，只增不减：若随 `versionName`
> 一起回退到 10000，已装拆库前版本（10400）的用户会因
> `INSTALL_FAILED_VERSION_DOWNGRADE` 无法覆盖安装，只能卸载重装并丢掉离线照片。

## 新增功能：拍照扫码

原流程是「手输条码 → 单张拍照」，本版新增扫码入口，改成两段式：

1. **扫码页**：带四角标记的取景框 + 遮罩 + 扫描线，实时识别二维码与条形码；
   12 秒无结果提示重试或改手动输入；相机权限三段式引导（授予 / 拒绝重申 /
   永久拒绝跳系统设置）。
2. **全屏连拍页**：预览铺满屏幕，只保留快门、已拍张数、返回三个元素；
   可连续拍摄并即时保存到本地。

| 环节 | 实现要点 |
|---|---|
| 解码 | ZXing（非 ML Kit）。ML Kit 依赖 GMS 动态下发，门店国产平板普遍无 GMS，装上后「扫任何码都没反应」且不报错；ZXing 纯 Java 离线可用，代价约 230KB |
| 相机 | 每个页面维护独立的绑定会话，**只解绑自己创建的 UseCase**（旧的 `unbindAll()` 会在导航过渡期把新页面刚绑好的相机一起解绑） |
| 预览不变形 | `FILL_CENTER`（等比裁剪而非拉伸）+ `COMPATIBLE`（TextureView，避免 SurfaceView 在导航过渡期穿透盖住 UI） |
| 生命周期 | 前后台切换、息屏均释放相机并在恢复时重新绑定 |
| 存储 | `files/photos/<安全条码>/`，命名 `条码_第N张_时间.jpg`，**默认不写系统相册**（凭证照片散落个人相册有隐私风险） |
| 路径安全 | 条码是外部输入，拼目录名前必过 `safeName()`，防路径穿越 |
| 后续上传 | 「完成」后逐张入队，由 `SyncManager` / WorkManager 补传，与手输条码流程共用同一套链路 |

## 兼容性

- **桌面端要求 ≥ v1.2.3**。低于该版本时「测试连接」仍可连通，但会提示
  「服务端版本较旧，原始上传与改备注不可用」，并自动降级为 base64 上传。
- `minSdk 26`（Android 8.0）/ `targetSdk 34`。

> 为什么是 1.2.3 而不是 1.3.0：桌面端 v1.2.3 就是首批带能力集接口（`system/capabilities`）
> 的版本，只是当时编号发成了 1.3.0。此处的最低版本常量若继续写 1.3.0，
> 桌面端报上来的 `serverVersion` 永远小于它，用户会被无限提示升级到一个并不存在的版本。
